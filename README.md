# SMM Аналитика — автосбор статистик 11 каналов + AI-аналитик

Полностью рабочее приложение по ТЗ: сбор данных, хранение истории, расчёт показателей,
недельные/месячные отчёты, AI-выводы с контролёром качества, аномалии, уведомления,
дашборд из 5 экранов.

## Быстрый старт (локально)

```bash
python -m venv venv
venv/Scripts/pip install -r requirements.txt   # Windows
venv/Scripts/python app.py                     # http://localhost:5000
```

При первом запуске создаются 11 каналов из ТЗ и демо-данные за 70 дней,
чтобы все экраны и отчёты сразу работали. Чтобы отключить демо: `set SMM_DEMO=0`.

## Деплой на Render.com

1. Залейте папку в Git-репозиторий (GitHub/GitLab).
2. Render → New → Blueprint → укажите репозиторий (подхватится `render.yaml`), либо вручную:
   - Type: **Web Service**, Runtime: **Python**
   - Build: `pip install -r requirements.txt`
   - Start: `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4`
   - Env: `PYTHON_VERSION=3.12.6`, `SECRET_KEY` (сгенерировать), `SMM_DEMO=1` для демо или `0` для чистой базы.
3. Создайте **PostgreSQL** (free) и привяжите `DATABASE_URL` — Render добавит её автоматически при создании БД в том же аккаунте (Internal Database URL).
4. Планировщик (ежедневный сбор 03:00, недельный отчёт пн 06:00, месячный 1-го 07:00) стартует автоматически внутри приложения.

## Подключение реальных источников

| Источник | Как включить |
|---|---|
| YouTube | Настройки: `youtube_api_key` + `youtube_channel_id` |
| AI-аналитик | Настройки: `ai_api_key` (+ `ai_base_url`, `ai_model` — любой OpenAI-совместимый API). Без ключа работает встроенный rule-based аналитик на тех же числах |
| Официальные выгрузки CSV | Экран «Импорт» (формат описан на экране) |
| Ручной ввод | Экран «Ручной ввод» (метрики со статусом MANUAL + контекст периода) |
| Лайфдюн / GetCourse | Ключи в настройках (`livedune_token`, `getcourse_api_key`) — коннекторы расширяются в `connectors.py` по тому же интерфейсу |

## Ключевые принципы (из ТЗ), реализованные в коде

- **История изменений**: значения не перезаписываются — таблица `metric_snapshots` хранит что пришло, когда, из какого источника, каким запуском (экран «История» по клику из отчётов).
- **Статусы данных**: OK / MISSING / NOT_AVAILABLE / ERROR / MANUAL / ESTIMATED. NULL никогда не превращается в 0.
- **Месяц ≠ среднее недель**: месячные ER/CV/ERR считаются заново из месячных абсолютов (`calc.indicators`).
- **Неделя пн–вс, месяц календарный**: пересекающаяся неделя относится к реальным календарным датам (`calc.week_bounds` / `calc.month_bounds`).
- **AI не считает цифры**: нейросеть получает уже рассчитанный JSON и только формирует текст; запреты (не выдумывать, не заменять NULL, «вероятный фактор» вместо причины) зашиты в системный промпт; AI-контролёр (`ai_analyst.controller_check`) сверяет отчёт с числами перед «отправкой».
- **Аномалии** определяются математически (отклонение от среднего 4 недель, пороги из ТЗ), AI только объясняет.

## Структура

- `app.py` — роуты, дашборд (5 экранов), планировщик
- `calc.py` — вся математика (ERR, ER, CV, CTR открытий, дочитывания, прирост, сравнения)
- `connectors.py` — сбор: YouTube API → CSV → ручной ввод; метки MISSING
- `ai_analyst.py` — классификация контента, аномалии, отчёты, AI-контролёр
- `reports.py` — формирование недельных/месячных отчётов
- `seed.py` — 11 каналов из ТЗ + демо-данные
